2.1  SCIKIT-LEARN (sklearn) — Version ≥ 1.3.0
-----------------------------------------------
  Role        : Core machine learning library; provides the Random Forest
                classifier, preprocessing pipeline, and model evaluation
  
  Key Classes and Functions Used:

  sklearn.ensemble.RandomForestClassifier
    — Primary prediction model
    — Parameters used:
        n_estimators  = 500        (number of trees)
        max_depth     = 18         (maximum tree depth, tuned via search)
        max_features  = 'sqrt'     (feature subset per split)
        class_weight  = 'balanced' (handles residual class imbalance)
        random_state  = 42         (reproducibility)
        n_jobs        = -1         (parallelise across all CPU cores)

  sklearn.model_selection.RandomizedSearchCV
    — Hyperparameter optimisation
    — 200 iterations, 3-fold stratified CV, scoring='roc_auc'
    — Search space:
        n_estimators:  [100, 200, 300, 400, 500]
        max_depth:     [8, 10, 12, 15, 18, 20, None]
        min_samples_split: [2, 5, 10]
        min_samples_leaf:  [1, 2, 4]
        max_features:  ['sqrt', 'log2', None]

  sklearn.model_selection.StratifiedKFold
    — Ensures class proportion maintained across all splits

  sklearn.preprocessing.StandardScaler
    — Feature normalisation (mean=0, std=1)
    — Fit on TRAINING SET ONLY; applied to validation and test sets

  sklearn.calibration.CalibratedClassifierCV
    — Platt Scaling post-hoc probability calibration
    — method='sigmoid', cv=5
    — CRITICAL for well-calibrated risk scores (Brier Score reduction)

  sklearn.metrics:
    — accuracy_score, f1_score, roc_auc_score, average_precision_score,
      brier_score_loss, confusion_matrix, classification_report

  sklearn.pipeline.Pipeline
    — Chains preprocessing (imputer → scaler) with model for safe deployment
    — Prevents data leakage during cross-validation

  Official Documentation:
    https://scikit-learn.org/stable/documentation.html

2.3  IMBALANCED-LEARN — Version ≥ 0.11.0
------------------------------------------
  Role        : SMOTE (Synthetic Minority Over-sampling Technique) to
                address class imbalance in PIDD (65% non-diabetic / 35% diabetic)
  
  Key Classes Used:
    imblearn.over_sampling.SMOTE
      — sampling_strategy='minority' (up-samples diabetic class to match majority)
      — k_neighbors=5 (nearest neighbours for synthetic sample generation)
      — random_state=42
      — APPLIED TO TRAINING SET ONLY (never to validation or test)

  Effect:
    Before SMOTE: 500 non-diabetic / 268 diabetic
    After SMOTE:  500 non-diabetic / 500 diabetic (balanced)
    Result: AUC-ROC improves from 0.921 → 0.991 (SMOTE-optimised model)

  Official Documentation:
    https://imbalanced-learn.org/stable/

3.1  SHAP (SHapley Additive exPlanations) — Version ≥ 0.42.0
--------------------------------------------------------------
  Authors   : Scott Lundberg, Su-In Lee (University of Washington, 2017)
  Role      : Primary feature attribution method; provides mathematically
              grounded local and global explanations using Shapley values

  Theoretical Foundation:
    SHAP values are based on Shapley values from cooperative game theory.
    For a prediction f(x), the SHAP value φᵢ for feature i represents
    the average marginal contribution of feature i across all possible
    feature orderings. Uniquely, SHAP satisfies:
      • Efficiency:   Σφᵢ = f(x) - E[f(X)]   (values sum to prediction)
      • Symmetry:     Equal contributors get equal credit
      • Nullity:      Zero-contribution features get φ=0
      • Linearity:    Linear model compositions are respected
    These properties make SHAP the most theoretically principled XAI method.

  Key Classes and Functions Used:

  shap.TreeExplainer(model)
    — Exact, O(T × L × D²) algorithm for tree-based models
    — T=trees, L=leaves, D=max_depth
    — Returns exact Shapley values (not approximations)
    — Used for: all primary SHAP explanations in MedTalk

  explainer.shap_values(X)
    — Returns a 2D array: [n_samples × n_features] of SHAP values
    — For binary classification: returns list of 2 arrays (one per class)
    — MedTalk uses: shap_values[1] (positive class = diabetic)

  shap.waterfall_plot(shap.Explanation(...))
    — Local explanation visualisation for individual predictions
    — Shows: E[f(x)] → feature contributions → f(x)

  shap.summary_plot(shap_values, X, plot_type='bar')
    — Global feature importance ranking (mean |SHAP| per feature)
    — Used in: Research paper Figure 5.3 and notebooks

  shap.dependence_plot(feature_name, shap_values, X)
    — Shows non-linear feature-prediction relationships
    — Used in: Glucose and BMI analysis (Figure 5.5)

  Configuration Notes:
    — check_additivity=False: Suppresses spurious warnings on calibrated models
    — shap.initjs(): Must be called in Jupyter notebooks before plotting
    — link='logit': Use for probability-scale visualisation

  Official Documentation:
    https://shap.readthedocs.io/
  
  Citation:
    Lundberg, S. M., & Lee, S. I. (2017). A Unified Approach to Interpreting
    Model Predictions. NeurIPS 2017.

3.2  LIME (Local Interpretable Model-Agnostic Explanations) — Version ≥ 0.2.0.1
----------------------------------------------------------------------------------
  Authors   : Marco Tulio Ribeiro, Sameer Singh, Carlos Guestrin (UW, 2016)
  Role      : Secondary feature attribution method; model-agnostic local
              surrogate approximation; used in fidelity-based selection

  Theoretical Foundation:
    LIME approximates the complex model f in the local neighbourhood of a
    prediction x by fitting a sparse linear model g:
      ξ(x) = argmin_{g ∈ G} L(f, g, πₓ) + Ω(g)
    where πₓ is a proximity measure and Ω(g) penalises model complexity.
    The linear surrogate's coefficients are interpretable as feature
    importances for that specific prediction.

  Key Classes and Functions Used:

  lime.lime_tabular.LimeTabularExplainer(
      training_data=X_train,
      feature_names=feature_names,
      class_names=['Non-Diabetic', 'Diabetic'],
      mode='classification',
      discretize_continuous=True
  )
    — Creates the LIME explainer fitted to the training distribution

  explainer.explain_instance(
      data_row=x_instance,
      predict_fn=model.predict_proba,
      num_features=8,
      num_samples=1000,
      top_labels=1
  )
    — Generates a local linear approximation for a single patient
    — num_samples=1000: Number of perturbed samples for surrogate fitting
      (reduce to 200 for faster but less precise explanations)

  explanation.as_list()
    — Returns: [(feature_name, coefficient), ...] sorted by |coefficient|

  explanation.as_pyplot_figure()
    — Horizontal bar chart of feature importances for this prediction

  Fidelity Computation:
    MedTalk computes fidelity for both SHAP and LIME on each prediction:
    fidelity = 1 - mean_squared_error(
        model.predict_proba(perturbed_samples),
        surrogate.predict(perturbed_samples)
    )
    The explanation with higher fidelity is selected for display.

  Note: LIME is non-deterministic by default. Set random_state in
  LimeTabularExplainer for reproducible explanations.

  Official Documentation:
    https://lime-ml.readthedocs.io/
  
  Citation:
    Ribeiro, M. T., Singh, S., & Guestrin, C. (2016). "Why Should I Trust
    You?": Explaining the Predictions of Any Classifier. KDD 2016.

4.1  STREAMLIT — Version ≥ 1.28.0
-----------------------------------
  Role      : Python-native web application framework; provides the entire
              MedTalk user interface without requiring HTML/CSS/JS expertise
  
  Key Streamlit APIs Used:

  Layout and Structure:
    st.set_page_config(layout="wide", page_title="MedTalk")
    st.sidebar.selectbox()      — Domain selector
    st.columns([1,2,1])         — Multi-column layout
    st.tabs(["Risk", "SHAP", "LIME", "Dialogue", "Audit"])  — Tab navigation
    st.expander("EDAQ Details")  — Collapsible sections

  Input Widgets:
    st.number_input(label, min_value, max_value, value, step, help)
    st.slider(label, min_value, max_value, value)
    st.selectbox(label, options)
    st.text_input(label, placeholder)
    st.button("Assess Risk")

  Output:
    st.metric(label, value, delta)    — KPI card for risk score
    st.pyplot(fig)                    — Matplotlib/SHAP plots
    st.plotly_chart(fig)              — Plotly interactive charts
    st.dataframe(df)                  — Audit log table
    st.download_button(label, data, file_name, mime)  — CSV/PDF export
    st.success/warning/error()        — Risk category coloured alerts

  State Management:
    st.session_state                  — Persists model, audit log across reruns

  Performance:
    @st.cache_resource                — Caches loaded model (avoids reload)
    @st.cache_data                    — Caches SHAP computations

  Deployment Note:
    Streamlit serves on localhost:8501 by default. For production deployment
    on a hospital intranet, use: streamlit run app.py --server.address 0.0.0.0
    with appropriate firewall rules and HTTPS reverse proxy (nginx).

  Official Documentation:
    https://docs.streamlit.io/
